# Multi-agent task assignment

**Recipe 49** · Level 4 (Advanced) · Decision type: `Score`

Score each agent's suitability for a subtask so a deterministic scheduler can assign work under capability, dependency, and budget constraints.

## What it teaches

Jev answers one narrow question, asked once per (agent, subtask) pair: how suitable is this agent for this subtask, given only the agent's plain-text track record and what the subtask needs? Python owns everything that decides who actually gets the work: which agents hold the required skill (capability), which subtasks must finish before another can start (dependency), and how much budget each agent has left. A deterministic scheduler combines a pair's score with those three constraints and a frozen confidence gate; a property test proves the three constraints hold for any scores Jev could have returned, by removing each one's enforcement in turn and showing the invariant it protects breaks.

## Switch to live

Live calls are opt-in and change nothing but the backend. Install the SDK
(`pip install -e ".[live]"`) and set `TYPESAFE_API_KEY`, `JEV_COOKBOOK_LIVE=1` and
`JEV_COOKBOOK_LIVE_MODEL`; then open `notebook.ipynb` from this folder in Jupyter (not a dependency
of this repository), or record answers with the recorder described in
[docs/live.md](../../docs/live.md). `tools/execute_notebook.py` removes those variables on purpose
and always runs offline. The live backend's default request budget is 25
(`JEV_COOKBOOK_LIVE_MAX_REQUESTS`, [docs/live.md](../../docs/live.md)); every attempt counts
against that budget, including each retry. This notebook decides each of its 74 examples exactly
once (one request per (agent, subtask) pair, cached by example id so a pair shown more than once
is never re-decided) and makes exactly **74** calls in live mode — above the default budget, so
raise `JEV_COOKBOOK_LIVE_MAX_REQUESTS` to at least 74 (more if you expect retries) before running
this notebook live, or it stops partway through with `BudgetExceeded`. Never put a key in a
notebook or a fixture.

## What was and was not measured

- **Mode:** synthetic (offline replay of hand-written answers). Not measured live.
- **Model, capture date:** not applicable while every answer is synthetic.
- **N:** 36 validation and 36 test (agent, subtask) pairs are scored (72 total; the 2 `demo`
  pairs, over a subtask no agent is capable of, are shown but never scored). The task-level
  "assignment quality against gold" figures in the notebook are over a different, smaller
  count: 6 validation subtasks and 6 test subtasks (one unit per subtask, not per pair).

The offline run replays synthetic answers written for this recipe, including one pair whose
stored answer is deliberately adversarial (a confident, high score for an agent who holds none
of the required skill), so its numbers check that the scheduler, the evaluation and the
constraint test behave as designed. They say nothing about how Jev performs, how fast it is, or
what it costs.
