# Evidence conflict diagnosis

**Recipe 47** · Level 4 (Advanced) · Decision type: `Choice`

Classify apparent claim conflicts by factual disagreement, time, entity, or scope using source excerpts and temporal relationships already computed by Python.

## What it teaches

An upstream system has already flagged two source excerpts about the same named subject as an
apparent conflict. Jev reads both excerpts plus a temporal relationship Python already computed
between their dates, and makes one `Choice`: a genuine factual disagreement, a difference
explained by time, by the excerpts sharing a name but describing two different entities, by
differing scope, or the named fallback, `not_conflicting`, for a pair that was never really in
conflict. Python owns the state (including the computed temporal relationship), the confidence
gate that decides which diagnoses are reported, and two zero-request baselines that show exactly
where Jev earns its keep against cheaper alternatives — and where, on this recipe's own
fixtures, a cheap feature beats it instead.

## Switch to live

Live calls are opt-in and change nothing but the backend. Install the SDK
(`pip install -e ".[live]"`) and set `TYPESAFE_API_KEY`, `JEV_COOKBOOK_LIVE=1` and
`JEV_COOKBOOK_LIVE_MODEL`; then open `notebook.ipynb` from this folder in Jupyter (not a dependency
of this repository), or record answers with the recorder described in
[docs/live.md](../../docs/live.md). `tools/execute_notebook.py` removes those variables on purpose
and always runs offline. The live backend's default request budget is 25
(`JEV_COOKBOOK_LIVE_MAX_REQUESTS`, [docs/live.md](../../docs/live.md)); every attempt counts
against that budget, including each retry.
In live mode this notebook makes exactly **36** calls, one for each of the 36 examples it
decides (16 `validation`, 16 `test`, 4 `demo`), and no other: `decide_once` caches by example
id, so a demo example shown in more than one walkthrough section is still decided once. That is
above the default of 25, so raise `JEV_COOKBOOK_LIVE_MAX_REQUESTS` to at least 36 before running
this notebook live, or it stops partway through with `BudgetExceeded`. Never put a key in a
notebook or a fixture.

## What was and was not measured

- **Mode:** synthetic (offline replay of hand-written answers). Not measured live.
- **Model, capture date:** not applicable; no answer came from a model. A recorded recipe names
  the model the API returned and the date or dates the answers were captured.
- **N:** 16 `validation` and 16 `test` examples are scored (36 in the fixtures; the 4 `demo`
  examples — including the required hard case and the adversarial case — are not scored). A
  recorded recipe states N beside every reported metric.

A recorded recipe states the model version the API returned, the capture date and N for every number
it reports, here and in the notebook.

The offline run replays 36 invented excerpt pairs with hand-written (synthetic) answers, some
wrong on purpose (one per scored split). Its accuracy, confusion matrix, and the baseline
comparison check that the pipeline works; they say nothing about how Jev performs, how fast it
is, or what it costs. This recipe has no recorded fixtures.
