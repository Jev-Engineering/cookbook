# AI livestream overlay verification

**Recipe 95 · Level 4 (Advanced) · Images + structured state + `Noul`**

Compare an agent's displayed phase, selected action and action status with readable gameplay
evidence. Six independent true/false propositions establish visual support and whether the
evidence can settle each claim. Python combines those judgments with exact timestamp checks,
labels each claim `supported`, `unsupported` or `unresolved`, and simulates a recommendation.

All 52 PNGs are authored 512 × 384 diagrams of a fictional game. They are generated by
`build_fixtures.py`, with no screenshots or external image sources. The bottom panel is the
agent overlay under verification; it cannot corroborate itself. Strategy text is displayed for
context, but strategic quality and real action success are outside the three defined claims.
There is no OBS, Twitch, game, browser, network or filesystem mutation in the policy.

From the repository root, after the development environment is installed:

```bash
python -m jev_cookbook.fixtures validate recipes/95-ai-livestream-overlay-verification
python tools/execute_notebook.py recipes/95-ai-livestream-overlay-verification
pytest recipes/95-ai-livestream-overlay-verification
```

Reproducing committed outputs requires Python 3.14 and
`.github/constraints-notebooks.txt`; see [development](../../docs/development.md).
`python recipes/95-ai-livestream-overlay-verification/build_fixtures.py` regenerates the PNGs,
inputs, labels and synthetic answers. A recorded response file requires explicit `--force`
before replacement; inputs and assets regenerate independently.

## Switch to live

The opt-in live path uses the identical questions and images through
`get_backend(fixtures=..., images=True, model="jev-1.14.0")`. Install the optional live SDK,
set `JEV_COOKBOOK_LIVE=1`, `TYPESAFE_API_KEY` and
`JEV_COOKBOOK_LIVE_MAX_REQUESTS=26` (or more to allow retries), and open the notebook in Jupyter.
The notebook makes exactly **26** calls: 12 validation, 12 test and 2 unscored demos,
each cached once.
The executor always runs offline. Images are experimental; the backend sends the image opt-in
header. No real calls were made while building this recipe.

## What was and was not measured

**Not measured live.** The committed run is synthetic: 12 validation episodes select a gate,
12 held-out test episodes report the frozen pipeline, and 2 demos show typed answers.
Each scored episode has 3 claim labels, so the test claim denominator is 36; each per-claim
metric and each event or routing metric uses 12 episodes. Deliberately authored errors include
a confident missed mismatch and a confident false alarm. Numbers are pipeline checks, never
Jev accuracy, latency, token usage or cost. `vision.run_record` leaves all synthetic resource
measurements and model names null.

The exact baseline receives the same raw claims, telemetry cache, images and timestamps,
then compares the claim strings with the telemetry strings. It does not interpret pixels.
The fixtures include a stale cache that agrees with an incorrect overlay, and a case where
the cache is right while the synthetic visual answer is wrong. This checks complementary
failure modes; it does not establish which method performs better on real streams.

Timestamp flags describe capture age and overlay lag on one shared monotonic clock with
zero allowed future skew. They do not prove that newly timestamped pixels are live:
a frozen image with renewed timestamps can pass. Semantic mismatch flags describe the
captured gameplay, independently of stream age. An occluded HUD, uncertain answer, contradictory
answer pair, unsupported claim, unknown claim or timestamp failure enters `ReviewQueue`;
all such routes leave `ActionLog` empty. Only fresh, fully supported claims produce an
unexecuted recommendation to retain the overlay. No text replacement is inferred from a
negative answer.
