# Abstention and review queues

**Recipe 38** · Level 3 (Intermediate) · Decision type: `Choice`

Route uncertain ticket classifications to review using thresholds selected from validation examples and measure accuracy versus coverage on a held-out set.

## What it teaches

A support ticket router that can abstain. Jev answers one `Choice` question per ticket, naming
one of three real queues or an explicit `insufficient_information` fallback. Python freezes a
confidence threshold from `validation` examples, routes a confident, queue-naming answer
automatically, and sends everything else — a low-confidence answer, or the fallback outright,
whatever its confidence — to a simulated review queue. The notebook reports the frozen rule on
`test` two ways: a plain per-question classification accuracy that ignores abstention, and the
coverage, accuracy and risk of the composed routing decision, plus the full risk-coverage curve
swept across every observed confidence.

## Switch to live

Live calls are opt-in and change nothing but the backend. Install the SDK
(`pip install -e ".[live]"`) and set `TYPESAFE_API_KEY`, `JEV_COOKBOOK_LIVE=1` and
`JEV_COOKBOOK_LIVE_MODEL`; then open `notebook.ipynb` from this folder in Jupyter (not a dependency
of this repository), or record answers with the recorder described in
[docs/live.md](../../docs/live.md). `tools/execute_notebook.py` removes those variables on purpose
and always runs offline. The live backend's default request budget is 25
(`JEV_COOKBOOK_LIVE_MAX_REQUESTS`, [docs/live.md](../../docs/live.md)); every attempt counts
against that budget, including each retry.
This notebook makes exactly one call for each of the 42 examples it decides (20 validation, 20
test, and the 2 demo tickets shown in "One answer up close" and "Python's part"), never twice:
raise `JEV_COOKBOOK_LIVE_MAX_REQUESTS` above its default of 25 to at least 42 before running this
notebook live, or it stops partway through with `BudgetExceeded`. Never put a key in a notebook
or a fixture.

## What was and was not measured

- **Mode:** synthetic (offline replay of hand-written answers). Not measured live.
- **Model, capture date:** not applicable while every answer is synthetic.
- **N:** 20 validation and 20 test examples (the 2 `demo` tickets carry no gold label and are
  not scored).

A recorded recipe states the model version the API returned, the capture date and N for every number
it reports, here and in the notebook.

The offline run replays synthetic answers written for this recipe, so every number above and in
the notebook checks that the pipeline works — the threshold selection, the routing rule, and the
risk-coverage curve — and says nothing about how well Jev actually classifies a support ticket.
No live or recorded call has been made for this recipe.
